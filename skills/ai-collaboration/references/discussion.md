# 討論模式

使用者指定雙方／三方就照指定；未指定時由目前 lead 加一名已獲授權的外部參與者，不自動增加 Gemini 或四方席位。模型依任務難度、風險與當前可用性選，不因省 token 降低必要能力。

1. 建立短題目文件：問題、有效要求、證據路徑、可選方案、完成條件。沿用專案既有紀錄位置。
2. lead 先寫立場；初輪題目只給底層材料，不給其他人的答案，避免看過答案才冒稱獨立判斷。
3. 收齊初輪後才互看。針對影響結論的點回答 `AGREE`／`CHALLENGE`／`COUNTER-PROPOSE`，附檢查證據；lead 回 `ACCEPT`／`HOLD`／`MODIFY` 及理由。
4. 關鍵分歧已解就收斂；只針對仍有實質問題且能補證據之處續談。真實全面同意可直接收案，不為形式製造對立。
5. 結論落到相關文件、spec 或程式，保留重要取捨、未解問題與推翻條件。原始回答留檔，不在每輪或壓縮後全文重載。

需要完整交叉質詢時讀 [交叉質詢](rounds.md)，人數沿用當次指定，不另載 skill 或暗增席位。
