# Clear status

1. Start with the practical answer: what is usable, finished, blocked, or still in progress.
2. Say what changed and what result was checked. Use ordinary words before internal labels or tool names.
3. State the limit of the check when it matters. If a later publication, deployment, or account step remains, name it plainly.
4. Give the next action only when someone needs to take it. Do not fill the answer with repeated reassurance, slogans, or unexplained hook messages.

Example: “The code is ready and the Windows and Linux checks passed. The package is on PyPI. The npm package is still waiting for account sign-in.”

Keep the update brief enough for the recipient to understand on the first read. Expand only when they ask for details or the decision requires them.
