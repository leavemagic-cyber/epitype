# Epitype 1.12.0

Released 2026-11-26.

This release lets owners limit enforcement to core rules, answers owner messages sent mid-turn, repairs rule cards an agent broke without touching owner wording, and replaces fixed size caps with limits the hosts actually apply.

## What changes

- **Core rules can be the only rules that bind.** With `"bind_only_core_rules": true` in `~/.epitype/config.json`, Stop and PreToolUse take triggers only from core-rule cards. Other cards keep their trigger fields as memory and fire nothing. `bind_also_cards` lists non-core cards that should still bind; misnamed or ambiguous entries are reported once at startup, with a time limit, and never widen matching.
- **Delivery is checked against its core rule.** A requirement card may declare `require_on_hit: block` when its reviewed source carries a blocking basis. A final message that claims delivery without the required text is blocked once; the rewrite is not checked again. Conditional future steps ("will ship once it passes") are no longer read as delivery claims.
- **Owner messages sent mid-turn get answered.** A card with `advise_on_midturn: true` and `advise_midturn_text` reminds the agent before its next tool call while an owner message sent during the turn is still unanswered. With `advise_midturn_on_hit: block`, the first tool call after such a message is refused once per message. Slash commands and host wrappers are not treated as owner messages; a subagent call, a missing session, an unwritable marker or an unreadable transcript never causes a refusal.
- **One advice card can bind a second trigger.** `advise_also_tool` with `advise_also_any_of` adds a reminder on another tool when any listed fragment appears in the call. A half-declared binding is reported as a card defect.
- **Broken rule cards are rebound automatically.** After an agent edits a rule card with a file-writing tool, Epitype rebinds it when only the body or unrelated fields changed. Edits that touch owner quotes, decision, status, guard or rule fields, or that cannot be classified, are not rebound; the editing agent is told what changed.
- **Size limits follow the hosts.** Memory indexes and host files are judged by real host load limits. `core_cap_bytes` is ignored with a one-line notice; core growth is compared with the last accepted baseline, card by card. Use `epitype core-baseline --accept --reason TEXT` to accept growth.
- **Recurrence review is a reminder.** A write that only adds narrative to a behavior card is allowed, with the review attached as a reminder instead of a refusal.
- **Compaction recovery is more reliable.** The resume block uses up to 8 KB. An unchanged handoff comes back as a path marked possibly stale, with the reason, instead of nothing. Subagent compaction no longer acts as the parent's.
- **Nightly maintenance stays out of the way.** The nightly dream waits while the machine is busy and retries until 07:00. It records per-section time, shapes over-limit `MEMORY.md` files into the full index, resyncs host files afterward, and leaves Codex-generated memory files alone.
- **Recall stays in the session's own project.** Recall is bound to the session's project, and a Latin letter joined to a CJK word is matched as one term.

## Known limits

- Mid-turn detection reads the local transcript tail. Hosts or sessions without a readable transcript get no reminder.
- Automatic rebinding needs a previously reviewed binding to compare against. Legacy cards without rule provenance, superseded cards and host-generated memory files are not adopted.
- Delivery blocking applies only to cards whose reviewed source carries a blocking basis, and only to the final message of a turn. Literal matching can still be bypassed by equivalent wording.
- Workflow checks remain advice. Host permissions remain responsible for irreversible actions.
- Public tests use synthetic fixtures and do not establish long-term effectiveness or compatibility with every host version.

## Upgrade or install

Requires Python 3.11+ and Claude Code or Codex with hook support. No manual data migration is required.

```bash
pip install -U epitype
epitype install --dry-run
epitype install
epitype doctor
```

Review the dry-run output before applying installation changes. Start a new host session after upgrading so the hooks load. For a fresh installation, use `pip install epitype` and the same installation checks.
