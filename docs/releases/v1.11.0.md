# Epitype 1.11.0

Released 2026-11-11.

This release reduces unrelated memory injection, restores useful working state after compaction, and adds tools for inspecting and budgeting startup context.

## What changes

- **Prompt matching is opt-in.** Ordinary prompts no longer search vaults or inject related cards by default. Explicit search, event capture, pending notices and compaction recovery work independently. To enable automatic matching, add `"proactive_recall": true` to `~/.epitype/config.json`.
- **Recall respects project scope.** Optional proactive recall checks ownership before ranking, excludes resident rules and prevents inactive or ineligible cards from introducing linked cards. Compaction recovery applies the same scope checks. Explicit search remains available for broader lookup and can find current cards using complete original phrases after summaries change.
- **Compaction restores current work.** Recovery prioritizes requirements, exceptions, decisions and unfinished work. If the full state cannot fit, a must-read pointer identifies the handoff. Parent and child contexts keep separate recovery state and delivery receipts; overwritten handoffs are detected, and only successfully emitted content is acknowledged.
- **Rules are reviewed by current content.** Routine maintenance checks meaning, scope and execution fields; historical conversation audits are explicit and optional. Generated advice remains bound to reviewed content. Compact rule metadata preserves full rule text and machine-readable recovery data, even when an advisory size target is exceeded.
- **Two new context-budget commands.** `epitype memory-index` previews lossless overflow into a full index, with one configurable byte budget (1,526 bytes by default); `--apply` is required to write. `epitype fixed-load` reports startup rules, indexes, tools and MCP registrations, separating estimates from observed runtime load. It never disables tools or blocks work.
- **Less maintenance work inside task conversations.** Startup reads cached lint results and incrementally warms action guards. Card-cleanup, alias and fixed-load maintenance notices stay out of hook context. Use `epitype cards <vault> --refresh-cache` to refresh lint results explicitly.
- **More accurate host reminders.** Claude Code supports token-based compaction windows and compatible learned thresholds. Completion-claim and deletion reminders are scoped more narrowly, localized Stop messages are preserved, and delegation is distinguished from verification.
- **Captured events stay unreviewed.** Human events are saved as explicitly searchable drafts with no rule authority. Tool results and compaction summaries are excluded; non-interactive Codex exec sessions skip capture. A shared collaboration skill supports both hosts.

## Known limits

- Optional proactive recall uses lexical evidence across writing systems. Ambiguous matches and missed paraphrases remain possible; multi-topic prompts may require explicit search. Resident rules remain available through explicit search.
- In Codex sessions without a local transcript, including ephemeral sessions, Stop reminders are unavailable and tool reminders may repeat.
- A handoff pointer must still be read by the agent. Recovery and hook output have size and time limits.
- Without a configured Claude Code token window or compatible observed compactions, the context meter has no threshold and sends no reminder.
- Workflow checks and Stop observations provide advice. Explicit action guards and retained safety checks can refuse matching calls, but literal matching can be bypassed by equivalent wording. Host permissions remain responsible for irreversible actions.
- Starter cards are AI templates saved for review under `_drafts/starter_templates/`; installing them does not activate rules. Public tests use synthetic fixtures and do not establish long-term effectiveness or compatibility with every host version.

## Upgrade or install

Requires Python 3.11+ and Claude Code or Codex with hook support. No manual data migration is required.

```bash
pip install -U epitype
epitype install --dry-run
epitype install
epitype doctor
```

Review the dry-run output before applying installation changes. Start a new host session after upgrading so the hooks load. For a fresh installation, use `pip install epitype` and the same installation checks.

Optional starter templates: `epitype starter`. Remove untouched starter cards with `epitype starter --remove`.

To uninstall, preview with `epitype uninstall --dry-run`, then run `epitype uninstall`. Native memory and cards remain in place.
