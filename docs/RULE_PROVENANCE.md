# 規則原始來源與生成入口

規則卡是共同資料來源。新規則與既有規則的實質修改，須保存原句、原始訊息位置與雜湊、文字作者、適用範圍，以及取代關係。使用者批准 AI 整理不會把 AI 文字變成使用者逐字原話。

## 卡片資料

核准的英文執行卡可用 `rule_provenance: {"ref": "<absolute retained-source JSON>", "sha256": "<SHA256>"}` 指向中文版留存資料中的完整來源文件。每次解析重讀並核對完整文件雜湊；不允許巢狀引用，完整來源與正文綁定仍走相同驗證。引用文件的 `approval` 可保存批准者及日期，英文卡不必重複保存引句與日期。`core_display: plain` 只在來源通過驗證時生成規則正文；作者、原句、日期及取代資料留在來源文件，不注入上線正文。其他卡保留原顯示方式。

`rule_provenance` 使用 JSON 字串，沿用目前 YAML 檔頭讀取方式。內容包含：

- `version`、`key`、`kind`（`owner-directive` 或 `ai-derived`）、`author`、`quote`、`text`。
- `sources`：原始 JSONL 路徑，或 ZIP 路徑及確切 member；實體行或 byte offset、`record_sha256`、session、訊息識別值及原始角色。只儲存指標，不複製完整對話或解壓大型封存。
- `scope`：global/project/case/action 層級、project、case、actions、conditions、expiry、exceptions。未指定期限寫 `unspecified`，不自動推成永久授權。`actions: ["*"]` 必須明示，不能由共用庫位置推定。
- `scope_basis`：支持範圍的確切原句、來源序號、審查者、日期與理由。短同意須另連接同場較早的原始 AI 提案，不把提案文字冒稱使用者原話。
- `supersedes`：被取代卡片的明確身分。改變規則身分或範圍時，另列 `supersession_basis` 保存原範圍及新決定的原文依据。
- `payload_binding`：完整正文及執行欄位的雜湊、審查者、日期與理由。禁止只核摘要，卻在正文或攔截欄位新增限制。真正會影響攔截的 aliases 也必須納入；純查找別名維護不創造新規則。

`rule_pipeline.bind_payload(document, card_text, reviewer=...)` 在已逐項檢視完整內容後建立綁定。必須先核對語義，再建立雜湊；函式本身沒有理解原文或授權動作的能力。

## 驗證及生成

使用者明確核准 AI 整理後，`approval` 可保存同一原始人類來源序號、逐字批准引句及 `text_sha256`。原始角色與引句、文字雜湊、核准語意標記及範圍審查來源都相符時，該已核准文字不再被當成 AI 根據觀察自行新增的限制；作者仍是 AI。這不替代正文綁定、範圍、取代鏈或實際動作授權，也不把一般未核 AI 限制升格為批准。

`python -m epitype rule-source <card>` 唯讀驗證原始訊息、完整正文／執行欄位與取代鏈。來源原句必須真正存在於相符角色的原始訊息；摘要、工具結果、代理轉述及機器包裝不能冒充使用者。原句即使出現在使用者貼回的 AI 前文中，也不能當新的使用者裁定。

寫入檢查、規則生成、交接裁定、喚回、壓縮後補送、決策檢查與停止時的裁定讀取共用相同資料及驗證。來源無效的卡不得回退成已核裁定；生成失敗會保留現有輸出並報出原因，不能以少掉壞卡的片段覆蓋整份規則。

2026-10-04 起，原始對話路徑失效或原件暫時無法讀取，只是來源未核的提示，不阻擋 `core-gen` 或 `sync`。生成保留卡片內容、記載作者與範圍，明列 `UNVERIFIED`；完整正文及執行欄位仍須符合既有綁定，取代鏈仍須互相指向，已過期或退場的卡不復活。原生設定同步沿用相同規則，保留原有事件範圍與使用者設定。實際讀到的雜湊／角色錯誤、正文變動及格式錯誤仍如實報錯。此發布提示不把缺失原件升格成已核使用者原話或工具動作授權。

來源及完整內容通過共同檢查後，原生設定清單明寫 `[]` 代表撤回該卡原有設定；不因卡片的提醒文字有自然語言條件而拒絕清除已退場的阻擋。仍有有效原生設定值時，照原事件範圍判定；格式或綁定有問題仍保留原設定並報錯。

每次使用會重新核對原始記錄的雜湊；快取只幫忙查找，檔案大小與修改時間未變也不能當原文未變的證明。喚回預算不足時交付明確指路或省略診斷，不截出丟失作者、原句與範圍的半段文字，也不把指路記作全文送達。

對機器能明確確認的專案／案件範圍，使用真正事件內的 context。沒有可靠 context，或條件與例外只以自然語言表述時，保留限定參考及缺口說明，不擅自擴成全域攔截。這份資料契約不增加使用者逐動作批准，也不授權交易、帳戶或其他外部操作。

## 舊卡與語義界線

來源尚未遷移的舊卡維持既有查找與宿主相容行為，標為來源尚未驗證，不把格式檢查成功算成原話正確。Core 保留舊正文並加一次未核圖例、來源庫與逐卡清單指路；不是把舊內容重新批准。工具提示也明示未核作者與來源，保留原有具體規則及比對條件；既有顯示語言的精確輸出快照因此增加這些標示。

既有資料可由主責在明確核對變更後，選定卡片路徑及完整內容的指紋生成一次基準。`rule_source_baseline` 指定此小型清單，`rule_source_baseline_sha256` 固定清單原始位元組；兩者須同時設定。讀入時重新核對清單與卡片，新增路徑、改義及變更後的清單均不能自動收納。既有成員移除規則類型或執行欄位仍須比對原指紋。相符僅代表與基準內容一致，來源狀態仍是 `UNVERIFIED`；基準不是使用者原話、批准或作業授權。

一般日期與純查找別名維護可沿用；新增正文、執行條件、作者／範圍或取代解讀必須完成來源核對。直接透過 shell 寫檔也會在後續規則讀入時核對，不能宣稱已攔住所有作業系統寫入。未設定基準時保留舊版相容行為並標未核；設定本身須依既有授權流程維護，這不是作業系統防竄改。

生成、停止裁定、工具守衛、喚回與壓縮後補送使用同一份內容快照；正文變動不能沿用已核身分與另一版本的檔案雜湊。工具守衛快取只定位卡片，在真正使用前重讀，並以實際事件核對專案、案件、動作、條件與例外；缺少可靠範圍時保留限定參考及診斷。文字出現「再試一次」不能證明已失敗三次或沒有合法重試條件；此類語言線索只提供原政策提醒，並保留實際比對到的文字。

`VERIFIED` 證明原句及角色相符、已保存範圍審查與完整內容綁定。輸出仍明列 `semantic_entailment: REVIEW_REQUIRED` 與 `action_authorization: false`。逐條語義核對和舊卡修正是獨立驗收項，不能從雜湊或合成測試推論已全面完成。

## 自動捕捉、轉正與範本發布

實際發布入口同樣檢查來源資料、作者、範圍與完整最終卡片。自動捕捉缺少完整來源資料時，原句與問答上下文留在 `_drafts/captured_pending`，來源狀態為 UNVERIFIED；捕捉位置只供路由，不推定全域或永久適用。`verified: true` 與歷史標記不能替代來源驗證，歷史捕捉保留在不注入的 `_drafts/captured_history`。

來源已綁定的卡片移動時保留已核身分、description 與完整正文；命名碰撞不能偷偷改名重綁。既有卡片原地不寫的相容操作不等於來源通過。沒有完整來源的內建 AI 範本保存為 `_drafts/starter_templates` 提案，不進索引或宣稱已安裝裁定。這些資料區分不增加使用者批准次數；既有明確授權仍按原範圍執行。

合成測試使用各自的 home 與設定，正例保存真正的合成 user 記錄及範圍審查；負例仍走實際發布與來源檢查。測試設定不修改現用固定基準，也不代表真實歷史來源已完成遷移。

## 原生設定的舊卡身分

固定雜湊基準的 v1 保留原先全成員檢查。v2 增加明示 `native_paths` 清單，須是 `entries` 的絕對路徑子集；Windows 路徑依大小寫不敏感的身分正規化，重複路徑、錯誤型別、未知成員與多餘欄位均拒絕。基準路徑與固定 raw-byte SHA256 pin 每次重新讀取驗證，只快取位元組完全相同的不可變解析結果。版本變更不改 `entries` 成員或內容雜湊，也不驗證使用者作者或新增動作授權。

原生設定同步在 v2 檢查原生身分清單、目前宣告原生執行欄位的卡、範圍明示 `host_sync`／`host_native`／`host_settings`／`native_settings` 的來源資料，以及同一實際目標庫組的既有 ownership-state 卡片引用。來源、完整正文／執行欄位、取代、期限與事件範圍仍走共同驗證。無關普通卡改義不阻擋原生設定批次；其他規則生成、喚回及停止檢查仍保留完整 `entries` 的改義防線。

狀態檔引用須是可見的相對 `.md` 路徑，不能跨庫、含 `..`、指向索引或隱藏檔。v2 引用缺失、重名或讀取失敗均拒絕，保留既有設定；有原生身分的卡刪除執行欄位也必須通過原來源檢查與有效退場資料，不能將空集合當刪除授權。v1 與未配置基準保留既有相容行為，來源不足仍明列 UNVERIFIED。

`rule_legacy.build_baseline(entries, native_paths=[...])` 或 `python -m epitype.rule_legacy --entries-json <explicit mapping> --native-paths-json <explicit list>` 僅生成 v2 候選。清單由已保存的初始原生卡清單明示遷移；工具不重新掃庫、自動納入新卡或更新 pin，正式採用由主控依既有授權治理執行。
